# IDRM — End-User Guides

Task-oriented guides for the people who *use* IDRM day to day — written in plain language, one per role. Where the
rest of [`../`](../) explains how IDRM is *built*, these explain how it is *used*.

> Structured on the **Diátaxis** approach (task-focused how-to guidance) and conformed to the posters' user-journey
> content (Posters 7–8). For the roles and permissions behind these journeys, see
> [`../05-security.md`](../05-security.md) and [`../mvp/22-architecture-security-and-iam.md`](../mvp/22-architecture-security-and-iam.md).

## Contents

| Guide | For | Covers |
|---|---|---|
| [`00-overview.md`](00-overview.md) | Everyone | What IDRM is for users, the shared concepts, and which guide to read |
| [`01-citizen-guide.md`](01-citizen-guide.md) | **Citizens** (affected people) | Raising a help request (incident), tracking its status, the guest path |
| [`02-responder-guide.md`](02-responder-guide.md) | **Providers / responders** (NGOs, hospitals, volunteers) | Registering an organization, finding nearby requests, accepting & completing them |
| [`03-coordinator-guide.md`](03-coordinator-guide.md) | **Coordinators** (government) | Approving critical requests, broadcasting alerts, verifying providers, reports |
| [`04-administrator-guide.md`](04-administrator-guide.md) | **Administrators** | User & organization management, oversight, the audit trail |

The four roles (**citizen · provider · coordinator · admin**) plus a guest path are the same roles enforced in the
code's RBAC — so these guides mirror what each role can actually do in the app.
